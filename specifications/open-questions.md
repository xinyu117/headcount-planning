# 待业务确认事项

以下事项来自《功能设计方案》V2.1 的缺失信息或章节间冲突。对应需求保持 `TBD`，AI 不应自行假设。

1. **单点登录链路（ACC-001）**
   3.3 同时描述“在 SuccessFactors 中直接进入 HCP”和“HCP 与 Azure AD 单点登录”。需确认 SF 入口的 SAML/OIDC 信任关系、用户唯一标识、回跳地址、登出联动及本地会话失效时间。

2. **年度基本预算期间（PLAN-005）**
   方案说明基本预算“一般为 3 年”，但截图和部分描述使用了单一年度。需确认标准列结构、跨年切换、非标准年度及历史版本展示规则。

3. **流程通知范围（PLAN-015）**
   2.2 要求流程每个阶段自动通知和提醒；3.4 称过程邮件待定；3.6 允许线下提醒且可不开发邮件提醒。需确认系统站内消息、邮件、待办以及邮件触发时点和收件人。

4. **导入能力与角色（PLAN-018）**
   2.2 要求支持 CSV/Excel 导入导出；3.4、3.5 明确部门与招聘只能导出不能导入。需确认管理员是否可导入、可导入对象、模板版本、错误处理及导入后的流程状态。

5. **招聘可行性评估（PLAN-014）**
   需求要求招聘团队评估可行性并在必要时调整，但未定义结论枚举、调整字段、是否覆盖部门需求、是否需审批及最终值计算规则。

6. **汇总行规则（PLAN-008）**
   仅举例销售 MR 汇总，未列出其他适用部门、纳入职位/职衔、精确公式、舍入规则及汇总行是否可导出。

7. **模板与公式配置（PLAN-001）**
   未定义模板字段配置、公式 DSL、版本发布、历史计划重新计算、颜色默认值及按部门覆盖范围。截图中的 `#D9EAD3`、`#DDEBF7` 和部门代码仅为示例，不能作为生产默认规则。

8. **报表目录（PLAN-017）**
   未定义报表清单、统计维度、全公司统一视图字段、筛选、权限、刷新频率及导出格式。

9. **数据保留与脱敏（ACC-004、PER-005）**
   未定义登录日志、人员个人信息、计划版本和导出文件的保留期限、脱敏字段与删除方式。

10. **SuccessFactors 元数据（ORG-001、PER-001、PER-002、POS-004）**
    方案列出了业务字段，但未提供目标租户 OData 实体、字段 API 名称、主键、删除/失效语义、认证、限流和增量同步策略，必须以目标租户 `$metadata`、API 权限及实际响应确认。

11. **多角色与组织范围（ACC-003、SEC-002）**
    需确认多角色是取并集还是拒绝优先、组织树是否包含下级、跨组织兼任如何处理、管理员是否默认全公司可见。

12. **招聘汇总性能指标（PLAN-019）**
    需提供实际最大部门数、人员行数、历史列数和可接受的加载/保存响应时间，用于形成可验收的性能基线。
